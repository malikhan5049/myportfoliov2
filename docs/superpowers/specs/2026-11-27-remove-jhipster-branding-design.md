# Design: Remove JHipster branding from the user experience

Date: 2026-11-27

## Intent & why

The apps are generated by JHipster, and the JHipster branding leaks into what a user
sees: the home page, the browser error page, startup log banners, navbar/loading/hero
images, PWA icons, and the Keycloak login page. The product is titled **My App Store**.
Goal: nothing a user of the running system sees should say JHipster. JHipster may remain
in code, comments, config, and generator files.

## Goals

- Rebrand all visible UI text: home pages, browser error page, startup banners.
- Replace visible JHipster images (navbar logo, loading logo, hero art, PWA manifest
  icons) with new "My App Store" brand images; rename files to `my-app-store-*`.
- Keycloak realm display name → "My App Store".
- Frontend + backend tests pass for all three apps after the change.

## Non-goals / anti-goals

- No renaming of `jhipster.*` config keys (read by `tech.jhipster` framework libraries —
  renaming breaks the framework). They remain visible only as technical config in the
  admin Configuration screen.
- No renaming of the Keycloak realm *id* (`jhipster`) — would invalidate docker-compose
  auth wiring. Only display names change.
- No renaming of `react-jhipster` npm library, `app/shared/jhipster/` module paths,
  code comments, `.yo-rc.json`, JDL, READMEs, or build scripts.

## Approach chosen

Single sensible approach: a text sweep + generated replacement images + verification.
Alternatives considered: (a) text-only sweep (rejected — the JHipster logo art on
navbar/loading/hero/icons still brands the app); (c) full framework-level rename
(rejected — high risk of breaking the framework for no user-visible gain).

## The parts already decided

- Brand name everywhere: **My App Store**.
- Home pages: "Welcome to My App Store" + neutral welcome content; the JHipster
  marketing link block (homepage/Stack Overflow/bug tracker/chat/Twitter/GitHub star)
  is removed, not restyled.
- Browser error page (`index.html`): keep the debugging guidance, strip JHipster wording
  and links; keep div id functional but rename to `app-error` (JS reference updated).
- `banner.txt`: "My App Store" branded Spring Boot banner.
- Images: generate a new logo + app icon; resize icon to manifest sizes (192/256/384/512)
  with a PowerShell System.Drawing script; new filenames `my-app-store-logo.png`,
  `my-app-store-icon-{192,256,384,512}.png`, `my-app-store-hero.svg` (hero may be
  generated PNG converted or replaced with a neutral SVG).
- Keycloak `docker-compose/realm-config/jhipster-realm.json`: `displayName` and
  `displayNameHtml` → My App Store; role description wording neutralized.
- i18n: only `en` locale exists; update `home.json` (+ remove stale keys),
  leave `global.json` `jhipster-needle-*` marker values (dev-only, not rendered).
- Tests: none assert on visible JHipster text (verified in inventory), so no test
  architecture changes; run suites to confirm.

## What's left to the builder

- Exact copy for the new home page and banner text.
- Exact image generation prompts and final look of the logo/icon/hero.
- Whether the hero art is a generated image or a neutral SVG replacement.
